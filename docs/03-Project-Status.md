## 3. 已确认的产品与技术决策

1. OntologyOps 是本地单租户的企业 AI Native 转型 MVP，不是轻量上传聊天 SaaS。
2. 首个领域为采购、供应商、物料、库存、质检；平台必须可由不同领域的新数据/文档创建新本体。
3. 本体包含 semantic elements（对象、属性、Link）与 kinetic elements（函数、规则）；Action/写回留到独立后续阶段。
4. 数据源、数据集、管道、质量规则、映射、本体版本、策略、Agent 工具调用必须构成真实资源链。
5. 智能助手是唯一应用层：企业数据问题只能调用当前发布本体编译出的、已授权、只读工具；其他问题可走不读取企业数据的通用模型路由，不生成或执行自由 SQL。
6. 模型仅支持 GPT、DeepSeek 与显式 Mock；Mock 不得伪装为真实模型调用。
7. 技术基座采用 FastAPI + React/Vite + SQLite + Parquet/DuckDB 的模块化单体；不引入微服务、向量库或工作流引擎。
8. 现有固定工厂 SQL、关键词 Agent、固定风险答案和硬编码权限属于 legacy，不得作为 v1 验收能力。
9. 任何验收均须以新上传数据跑通；种子数据只能用于开发测试。
10. 当前仓库已建立 `main` / `dev` 初始基线，远端为私有仓库 `GroMach-AI/ontologyops`；未经过本地验收与负责人确认的能力不得合入 `main`。

- 本文档只记录可验证事实；页面存在、代码存在或单测通过不等同“浏览器验收通过”。
- 每完成一个模块，更新其 PRD、原型、技术设计、开发和浏览器验收状态，并链接对应测试/截图/运行 ID。
- 遇到范围变化、风险、关键决策或验收失败时，先更新本文档，再进入下一阶段。
- 产品运行代码和本地验收状态以实际 Git 提交、`local-*` / `release-*` 标签及项目负责人确认作为准据。
