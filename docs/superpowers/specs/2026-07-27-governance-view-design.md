# 治理与可追溯展示页设计

## 目标

将“治理与可追溯”收敛为 Demo 的证据查看台。用户可快速核验数据规则状态、资源来源和一次智能助手结论的证据，不在本期承担完整治理配置工作。

## 范围

仅修改前端路由 `/governance` 及其测试、样式。保留现有后端接口与其他页面，不新增 API、不改变数据模型、不移除已有后端治理能力。

## 页面结构

主内容采用两栏：左侧为可切换的三个展示视图，右侧为固定的“最近事件”时间线。

1. **规则结果**，默认视图。展示质量规则名称、目标数据集与字段、最近状态、异常数量。仅允许刷新和运行已有规则；不提供新建、编辑、异常样本展开、筛选或权限模拟。
2. **数据血缘**，展示从来源数据集、清洗或质量运行、映射到当前本体版本的线性资源链。缺少资源时使用明确空态，不以预置样例替代真实数据。
3. **可追溯性**，展示一条受控问答证据链：审计事件、资源类型和发生时间。它回答“谁在何时对哪个资源做了什么”，不重复展示权限配置。
4. **最近事件**，固定显示现有审计接口返回的最近事件，作为跨上述三类视图的统一时间线。

## 删除内容

- 新建质量规则及其表单
- 权限预览卡片
- 质量统计卡片
- 复杂说明、筛选器和异常样本详情
- 页面内“模拟授权”等演示动作

## 行为与数据边界

- 页面继续调用既有质量规则、审计、血缘接口。
- `运行` 仅对已存在规则可见，并沿用当前角色权限控制。
- 页面加载失败或某类资源为空时，以说明性空态展示，其他区块不受影响。
- 页面不创建、修改或删除规则配置。

## 验收标准

- 治理页只出现“刷新”这一页级操作，规则行可保留“运行”。
- 三个页签可切换，默认规则结果。
- 最近事件固定显示在右栏，并读取真实审计接口结果。
- 规则状态、血缘、审计均来自现有 API 返回，不写入固定制造业演示数据。
- 现有模型、本体、管道、智能助手路由与交互不改变。
